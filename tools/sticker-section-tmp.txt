── WHERE STICKERS LIVE (MANDATORY ROUTING) ─────────────────────────────────────
  Core plant (herb, flower, veg, shrub, tree)  →  usePlantCatalog.js ONLY
  Cactus / Succulent                            →  pack-cacti-succulents.js ONLY
  Palm / Tropical                               →  pack-tropical.js ONLY
  New pack type                                 →  create new pack file + register in packs/index.js
  NEVER add a plant to more than one location — duplicates cause double entries in the tray.

── STICKER ADDITION WORKFLOW (v2 — approved June 2026) ─────────────────────────

  PHASE 1 — GENERATE (no upload, no commit)
  ──────────────────────────────────────────
  1. Run sticker-generate-one.py for each requested plant (NO --force, NO auto-upload)
  2. Generated PNG lands in: stickers/generated/pending/<key>.png
  3. Script sends NO Telegram previews automatically (Telegram path is broken — send manually)
  4. Computer sends all pending PNGs to Rob via Telegram message tool for visual review
  5. Rob reviews PNGs locally at the full filepath provided

  PHASE 2 — APPROVAL
  ──────────────────────────────────────────
  Rob replies with one of:
    "Approve [name]"      → proceed to commit that sticker
    "Redo [name]"         → regenerate with same or updated prompt
    "Skip [name]"         → discard pending PNG, do not commit
    "Approve all"         → commit all pending in one batch
    "Redo all"            → regenerate entire batch

  PHASE 3 — COMMIT (only after explicit approval)
  ──────────────────────────────────────────
  1. Copy PNG to app/public/stickers/ AND stickers/ (both locations always)
  2. Add entry to correct file (catalog or pack — NEVER both)
  3. Run validate-tray.ps1 — must show 0 errors before committing
  4. git add -A && git commit -m "Sticker: add [Name] ([key])"
  5. git push (Vercel auto-deploys)

── STICKER EDITING WORKFLOW ─────────────────────────────────────────────────────
  Regenerate with new prompt:
    python sticker-generate-one.py "[Name]" (no --force)
    → sends to pending/, Rob reviews
    → on approval: Copy-Item new PNG over existing PNG in both locations (in-place replace)
    → key UNCHANGED — saved gardens continue working
    → commit: "Sticker: replace [Name] image (v2)"

  NEVER:
    - Delete a key from any catalog or pack file
    - Delete a PNG that is referenced by any key
    - Rename a key (add a new key alongside instead; old key stays as alias in useSaveLoad KEY_REMAP)

── DUPLICATION PREVENTION RULES ────────────────────────────────────────────────
  Before adding any sticker, run:
    pwsh tools/validate-tray.ps1
  Must show 0 errors. If duplicate detected → fix routing first, then add.

  The add_to_catalog() script checks for EXACT key match: key:'<id>'
  Never use partial string matching to check for existing keys.

  Daily cron (9 AM ET) runs validate-tray.ps1 and pings topic 3954 on errors.

── STICKER CONTINUITY RULE (L025) ──────────────────────────────────────────────
  Never delete a key. Never delete a PNG that is still referenced.
  Replace = overwrite PNG in-place. Retire = hidden:true in catalog entry.
  Missing key = broken image in any saved garden containing that plant.
  If a key changes size (e.g. M→S): add KEY_REMAP entry in useSaveLoad.js, keep old PNG as orphan.
