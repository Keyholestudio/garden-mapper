Garden Planning Tool:


Before we action anything, I’ve added the ‘Expanded app plan” tab to this document. That’s where we will be working and expand on what I have written below. We will build out a plan for the app, add inspiration graphics, and highlight areas that we need to focus on before acting on them. Please read the plan below, create a project plan for this, use subagents to research the tools needed for tool building (create a framework of what’s needed for now and future uses -- I want to build with the future in mind but keep costs to a minimum till we have a workable tool). A subagent to research garden planning tools that already exist like this, read the reviews of these tools and find common complaints and preferred features by the users that we should consider when building out the plan. Please also research the process of creating a cohesive theme for an app that includes things like creating textures for apps, etc.


The goal is to create an interactive gardening web based tool that’s accessible on a tablet/webpage and, in the future, a mobile phone compatible app. Webpage compatibility with kofi.
We, for now, can self-host and use the trycloudflare link as the tunnel that will provide the URL (Like we have set up on our marketmap tool)
I want to be able to show a drawing of my garden/property. I want to be able to drag and drop “stickers” and/or a label of the flower/plants in my yard.

This app will allow me to:
Set the time of the year (Spring, summer, fall, and winter) as a slider at the bottom of the screen.
* When changing seasons, plants like tulips will be selected for spring and summer and I can toggle them off for fall and (by default) winter. 
* The colour of the landscape/background colour will change a bit in each season. Spring green, summer dark green, fall oranges, winter white or beige.
We will create a catalog of graphical images of plants using image generation software.
We will create the ability to draw flower beds, decks, pools, buildings, fences and decor in the yard. These shapes will not be on the same layer of drag and drop as the plants, they will be in a sub layer beneath the plants and will be accessible in the “draw my property” section.
Scrape plant information: when to plant, when to harvest, what the soil ph should be, light conditions required.
Provide a link to a plant identification tool so people can figure out what their plants are.


Tools we will lean heavily on:
Image generation software to create images of the plants and trees.
* We will work to create a cohesive theme.
* We will use flat colours to start, but we will have to build a system where the flat colours are replaced by textures and images of plants that we have on file and have created together. 
* The stylistic choices are not yet confirmed, so we will have to use basic colours and shapes for now, but we will have to be able to replace those shapes with created images.
   * I like the esthetic of stardew valley, however gardens are not always so heavily gridded. I would like a flowier version.


Example workflow:
Open the app
Log in
Select your garden (you may have different properties and want to select one or the other: Cottage or Home for example)
If you haven’t created a garden yet, you create one:
* Enter the name of the garden
* Then draw out the dimensions. The base layer utilizes snap to dimensions where you can draw out lines of the property on a grid. The flowerbeds can be rounded or square. You will draw in the garden beds and the can be coloured according to a drop down of colour options (browns, greys, tans). We will build out textures for that.
Adding plants: Then when the garden is created, you have a search bar for the plants and after you select one from the quicklist/most recently used list, you click and drag it from the list to its position in the garden.
* You can pinch and zoom or use the mouse zoom to map the garden larger or smaller and you can make the plant bigger or smaller as well.
* After you place the plant, you can select it to be given a list of options: delete, copy, create a range of this plant using points and lines (This will allow you to mark a border of a plant but now be required to copy, paste and move dozens of plants), add photo of the flower from your camera (upload from PC or accessible through the images on the phone, a notes section, a wikipedia scraped information secion that displays the plants basic information, and decide what seasons this plant should appear in.
* Change season on the slider at the bottom. Allowing you to access different seasons and see the garden in that season: a tulip sticker in spring can be a different size then the tulip in summer. And, may be not visible in fall and winter.
Everything is saved automatically.

══════════════════════════════════════════════════════


Layer          | Choice                   | Why
──────────────────────────────────────────────────────────────
Frontend       | React 19 + Vite          | Best Konva.js ecosystem; React Native path for mobile
Canvas         | Konva.js (react-konva)   | Native drag/drop, layers, pinch-zoom, Transformer
Backend        | FastAPI (Python 3.12)    | Fast, async, same pattern as other projects
Database       | PostgreSQL (Docker)      | JSONB for canvas state, multi-garden ready
Auth           | FastAPI JWT              | Self-hosted, lightweight
Styling        | TailwindCSS + CSS tokens | Seasonal swap = 6 CSS variable changes
Deploy         | Docker Compose + CF Tunnel| Same as MarketMap
Ko-fi          | Static embed widget      | Zero backend work, optional
